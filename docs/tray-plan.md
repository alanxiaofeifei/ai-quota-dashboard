# Windows 托盘伴侣计划（Issue #12，仅设计）

目标：浏览器关闭后仍可通过托盘和全局热键查看最后成功额度。该阶段不实现代码，不改变当前扩展和 Worker 鉴权模型。

选用 Tauri 桌面外壳与系统托盘。UI 复用摘要的明确单位、来源、账户标签、失败原因、过期时间与重置待确认行为。快捷键可配置，默认需避开 Chrome / 系统冲突；提供开机自启开关、窗口置顶开关、手动刷新，以及默认 60 分钟的刷新间隔（最短 15 分钟，允许用户调整）。恢复联网或从休眠唤醒时刷新摘要，失败保留缓存并标明离线，不补造数字。

设备通过用户在看板创建的设备码配对，使用独立可撤销 device token。令牌保存在 Windows 凭据管理器，不进入 Tauri 前端持久化、日志或系统启动参数；不导入浏览器 Cookie 或会话。HTTP 客户端只访问固定的用户看板 HTTPS origin，禁止重定向，使用设备 Bearer 请求 `GET /api/ext/summary`；设备初始化 / 心跳复用已有 `/api/ext/hello`、`/api/ext/heartbeat`，不访问普通所有者 API。Access 仍只对 `/api/ext/*` Bypass，浏览器页面和其他 API 保持保护。

原生端不负责爬取供应商登录页面，仅读看板已有快照。浏览器关闭时，扩展页面数据不会继续更新，必须清楚显示缓存年龄和「浏览器扩展离线」；公开 API 余额更新策略另行评审，不能在托盘端携带供应商密钥。Summary 不返回凭据或教学定位器。

后续验收包括：配对 / 撤销、同名账户隔离、设备令牌不可访问普通 API、托盘显示 / 隐藏、开机自启开关与卸载清理、全局快捷键冲突、置顶切换、不同 DPI、多显示器窗口位置、系统休眠 / 断网恢复、缓存过期和失败不变成 0 / 100%。签名、打包与自动更新安全机制在实现前定案；不在 v1.2 扩展修复中引入 Tauri 依赖。
