当前状态：**准备工具已实现，真实验证未通过，自动采集门槛仍关闭。**

开发环境为独立的 Linux 云环境。用户已授权临时安装官方 CLI；已隔离安装 Codex CLI 0.167.1，并完成下述无登录冒烟检查。安装和无登录检查不能继承用户 Windows 上的登录态，也不能替代 Windows 11、实际套餐及官方界面对照。没有读取真实凭据或聊天，没有部署或上传真实额度数据。

## 1. 现在可以执行的检查

在仓库根目录执行：

```sh
cargo run --locked -- doctor
cargo run --locked -- parse-codex --input fixtures/codex-rate-limits.json --output synthetic-report.json
cargo test --locked
cargo test --locked --features test-support
```

输出文件须尚不存在。`doctor` 不启动官方程序；离线解析只处理明确指定的文件。合成报告中的比例和时间仅用于测试。

验证器保留 `probe-codex` 命令以给出明确状态，但当前必定返回 `live_probe_unverified`、退出码 3，不启动 App Server。确认参数不能绕过这个门槛。默认发行程序没有真实子进程采集路径；模拟传输只服务测试。

独立脚本 `scripts/codex-unauthenticated-smoke.py` 用于已选定官方发行物的无登录协议检查，不开放默认验证器的真实账户采集。2026-11-11 的 Linux 检查结果为：版本 0.167.1；临时认证档案为空，`account/read` 返回空账户；额度请求因未认证而拒绝（RPC 错误码 `-32600`）；没有发起登录或模型任务，观测额度为 `null`，`real_account_verified=false`。

该次检查的网络隔离由外层 Linux network namespace 提供；脚本自身不宣称阻断网络。Windows 原生 App Server 0.167.1 的[无登录 CI](https://github.com/alanxiaofeifei/ai-quota-dashboard/actions/runs/42939400859)也已通过，确认空账户和已知认证拒绝；Windows 测试没有宣称采用同样的网络沙箱。[双平台离线检查](https://github.com/alanxiaofeifei/ai-quota-dashboard/actions/runs/42939327717)包括 Windows 诊断脚本、解析器及浏览器选区合成测试。以上只证明无登录与合成路径，不代表有认证时的刷新、凭据隔离或真实额度已经通过。

## 2. 真实验证开始前的条件

以下条件应逐项登记为通过或阻塞，不能由测试自动填成“已验证”。

- [ ] 确认新建本地只读开源应用适用的认证政策。官方文档对已有本地／开源应用的说明，不能自动扩大为对新应用或托管服务的许可。
- [ ] 由用户选定真实验证的产品、个人套餐和 Windows 设备；用户自行在官方客户端完成登录，不向聊天或仓库提供凭据。
- [ ] 固定待验证路径的客户端或浏览器版本及来源，检查启动、配置、页面读取权限、日志、缓存和认证刷新行为。
- [ ] 证明专用运行目录、受控工作目录、最小配置及操作系统凭据存储的隔离。不能把更换目录视为已完成密钥链隔离。
- [ ] 若官方认证必须落在文件中，先验证 Windows ACL 限定当前用户；本项目不为此预先生成认证配置或读取认证文件。
- [ ] 确认不会启动非必要插件／MCP／hooks，不继承日常项目配置或读取历史聊天。不能满足时保留阻塞，不能复制既有 token 兜底。
- [ ] 记录对必要认证刷新和本地运行状态写入的授权范围。业务只读不等于官方客户端完全不写文件。

默认账户验证器尚未实现登录、生成持久认证档案、白名单官方发行版或开放真实探测。无登录脚本只创建并清理自身空临时配置。后续只有上述条件明确后，才能提交一个经过评审的真实传输变更；不通过任意开关跳过验证。

CLI 是候选路径，不是唯一前提。官方文档提供[用量看板入口](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)；当前收到的可打开地址为 [ChatGPT Settings → Usage](https://chatgpt.com/settings/usage?tab=overview)，属于用户反馈的页面入口，尚未经本项目读取和核对。官方文档链接的旧 [Codex Usage 地址](https://chatgpt.com/codex/settings/usage)可能随版本重定向。可与 npm／CLI 诊断并行验证用户自己已登录的用量页面，不要求先修好全局终端安装。

## 3. Codex 的限定真实验证方案

未来获准并开放的探测仅采用独立子进程和 stdio，发送初始化、`account/read`（`refreshToken:false`）以及 `account/rateLimits/read`。额度读取前后再次读取账户状态，在内存中比对归属；发生切换则丢弃结果。报告不保存账户邮箱或认证数据。

不读取 thread／session／history，不调用模型，不消费 reset credit，不发邮件，不修改订阅。未知请求不授权、不执行；上游 stderr 和完整 RPC 流不进入日志。

按以下项目对照官方界面，记载观察日期、客户端版本和非敏感结论：

| 场景 | 验收要求 |
| --- | --- |
| 正常额度 | 同一账户、同一桶、同一窗口，使用比例与官方页面在观测时间差允许范围内一致 |
| 多桶／兼容视图 | 同一桶不重复计算；保留服务返回的模型组、窗口和共享池含义 |
| 缺字段／仅重置时间 | 显示未知，不生成零、满额、固定五小时或固定周窗口 |
| 订阅 credits | 保留明确单位，不换算成 API 余额或美元费用 |
| 无登录／API-key-only／过期 | 返回明确失败；不后台弹登录，不以零值替代，不自动切换账户 |
| 账户切换 | 查询前后身份不同即丢弃，不错贴旧请求结果 |
| 限频／断网／超时 | 保留最后观测时间和错误类别，不立即无限重试 |
| 时钟与重置 | UTC 保存；验证秒与毫秒、Asia/Taipei 和跨时区；预计重置到点不等于已恢复 |
| 进程与安全 | 不启动模型任务，不读聊天；无原始凭据、账户身份或完整响应进入报告／日志 |

不主动耗尽额度来制造边界；零、满额、空桶、非法响应、限频和竞态由合成测试补足。真实界面不提供的字段保持未知。

官方固定版本的公开 `features.plugins=false` 会阻止插件启动任务，见 [0.167.1 对应源码](https://github.com/openai/codex/blob/0a94398fa60c4fac0e7659e4213a0a36e613dd46/codex-rs/core-plugins/src/manager.rs)。因此不能笼统声称公开版本无法关闭插件；仍需核查该版本的其他启动行为、系统配置与认证存储，关闭一个功能不证明全部隔离。

正在实现的网页备选是默认关闭的前台实验验证器：用户在指定 Usage 页面主动选中额度文字并点击扩展，仅处理该选择，不抓整页、Cookie 或网络会话。目前真实页面读取尚未通过验证。它不是稳定公开 API，也不是关闭页面后继续运行的后台轮询；按其实际运行模式分别验收。终端命令不应成为未来用户每次查额度的必要操作。

## 4. Antigravity、Grok 和 Gemini 的后续位置

Antigravity 优先核查用户自行运行的官方 `/usage` JSON 报告；手工报告可帮助验证解析，但**不计入自动数据源通过**。官方只读命令能力和第三方定时封装的政策边界分开核查；内部 OAuth／语言服务器接口不进入默认方案。

Grok／Grok Bot／Gemini App 保留独立产品语义。指定额度页面读取需用户主动授权且核查政策；非公开接口默认关闭。当前工具没有实现这些采集器，不用开发者 API 用量替代消费者额度。

## 5. 进入下一阶段的通过门槛

至少一个自动数据源同时具备以下证据：

1. 政策适用性及用户授权明确。
2. 固定客户端或前台页面适配器在目标 Windows 环境运行成功，权限及认证副作用可接受。
3. 返回字段、账户归属和官方界面对照一致。
4. 缺失、失败、切换和重置场景不伪造数据。
5. 凭据、日志、报告及本地权限检查通过。

通过后才开发本地看板、SQLite 快照和轮询。若没有自动源通过，提交阻塞原因及调整建议，不把人工输入外壳当作计划中的自动 MVP。

私人 HTTPS、Tailscale、云同步、通知外发、公共多用户和发布均属于后续独立里程碑，当前不配置。
