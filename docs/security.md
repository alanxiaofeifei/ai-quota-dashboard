# 阶段 0 安全边界

当前交付是本地可行性验证工具，不是公网服务，也不是已经验证的多用户看板。没有云同步、外发通知、遥测或远程命令入口。真实探测保持关闭：`probe-codex` 返回固定阻塞错误，不启动官方进程。

## 信任边界

- `doctor` 只检查运行环境，不启动官方客户端，不读取凭据或聊天。
- 离线解析只读取用户明确指定的输入文件，输出已知额度字段，不保存原始 JSON。不要使用聊天导出、浏览器会话或认证文件作输入。
- 当前默认程序没有真实子进程采集路径；受控模拟子进程仅用于测试。未来真实探测必须使用用户显式指定、已审核的本地官方可执行文件，与独立 App Server 子进程通过 stdio 通信，不代理任意 RPC。
- 未来启动官方客户端会使用指定档案的认证；“验证器不解析认证文件”不等于“官方子进程不接触凭据”。它也可能刷新认证、写入日志或缓存。
- 不复制现有 token，不扫描浏览器数据库，不读取历史会话，不调用模型、不消耗重置权益、不充值、不发邮件、不自动登录。

## 专用运行目录与启动行为

真实探测前必须明确核查新应用的认证政策适用性，并确认所选 Windows 客户端版本支持所需隔离。专用目录与命名配置 profile、操作系统密钥链隔离是不同事项，不能只因为换了一个目录就认为已经隔离。

未来真实验证使用的运行目录应由用户按批准范围准备并完成官方登录。不要复用日常工作的项目目录、完整配置、插件、MCP、hooks 或历史会话。若系统策略、密钥链、全局配置或启动副作用不能可靠隔离，停止探测并记录阻塞，不自动降级到复制凭据。当前工具不生成认证档案，也不修改官方客户端配置。

验证器的 RPC 白名单约束的是它发出的请求，不是官方程序的所有内部行为。公开源码的 App Server 启动路径会初始化本地状态，并可能执行插件启动工作；必须逐版本审核，不能仅靠专用目录推定隔离。未来真实探测授权应包括可能的正常认证刷新；它不包括绕过验证码、访问控制、客户端保护或平台条款。

## 报告、错误与日志

- 不打印或保存子进程原始 stderr、原始 RPC 流、邮箱、访问令牌、刷新令牌或请求头。
- 输出只包含明确允许的额度摘要及验证状态。额度比例、时间、套餐或桶名本身也可能是个人数据，应保留在用户控制的目录内。
- 报告不包含凭据，不意味着可以自动公开；提交 issue 前仍应先阅读并删除不希望公开的摘要。
- 错误使用固定类别和安全文本，不反射上游错误全文、异常输入或本地敏感路径。
- 不生成“满额恢复”推断：缺字段、认证失效、请求失败、空快照和过期重置时间分别保留未知或失败。

## 权限与后续产品约束

工具以当前用户权限运行，不需要管理员权限。用户指定的可执行文件本身是受信代码，必须从官方渠道取得；验证器不是恶意可执行文件的沙箱。

后续看板仍需自己的鉴权、Host／Origin 检查、CSRF 和设备撤销。回环监听、私人 VPN、HTTPS 反向代理都不能替代应用鉴权。手机只能读取摘要，云端只能接收白名单摘要；不得把完整 App Server 暴露给其他设备。

未来开放多用户服务需要独立安全设计与验收。当前的本地路径和测试不是其安全证明。

## 发现问题时

立即停止真实探测，保留脱敏的错误类别、版本与复现条件。不要在公开 issue 附上认证文件、浏览器数据、完整上游响应或原始子进程日志。没有专门安全接收渠道前，只报告不含敏感细节的摘要。
